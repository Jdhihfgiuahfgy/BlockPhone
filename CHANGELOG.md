чтобы при поиске бага было видно, где и когда он мог появиться.

## [0.7.1] — 2026-10-20 — Доп.: плагин BungeeCord

- Новый модуль `bungee` — плагин для BungeeCord/Waterfall: мессенджер, лента, фото и голосовые общие для всей сети
  (как плагин Velocity). Канал `blockphone:main` обрабатывает прокси и не пропускает к серверам; приветствие при входе и каждом
  переходе между серверами. Настройки `plugins/BlockPhone/config.json`, драйверы H2/MariaDB внутри jar.
- Права на BungeeCord: модераторские — через систему прав (LuckPerms) или список `moderators`; обычные — у всех.

### Проверено
- `./gradlew :bungee:build` — jar собирается, внутри bungee.yml, общий код и драйверы.

### Не проверено (нужен ручной тест)
- Живой прокси BungeeCord с игроками.

## [0.7.0] — 2026-10-20 — Этап 7: Telegram и «кружочки»

### Telegram (`telegram/`, `apps/telegram/`)
- Настоящий Telegram через TDLib (библиотека TDLight 3.5.9, TDLib 1.8.68; нативная часть — только Windows x64, встроена в мод).
- Вход по шагам: ключи приложения (api_id/api_hash с my.telegram.org — инструкция и кнопка в телефоне) → номер → код → облачный пароль
  (поле со скрытым вводом). Понятные сообщения на частые ошибки (неверный номер/код/пароль/ключи, слишком много попыток).
- Список чатов (как в Telegram, закреплённые сверху), аватары, последнее сообщение, время, непрочитанные; значок на иконке.
- Переписка: пузыри, имена в группах, фото (докачка TDLib), обложки «кружочков», подписи вложений, подгрузка истории,
  отправка текста (Enter), отметка «прочитано». Уведомления о новых сообщениях (кроме чатов без звука). Выход из аккаунта.
- **«Кружочки» из кадров игры:** кнопка «◯» в чате → телефон закрывается, по центру — красное кольцо и таймер; кадры мира без
  интерфейса, 320×320, 15 кадров/с, до 15 секунд; клавиша телефона — отправить, Esc — отмена. Кодирование в MP4 (H.264) — JCodec
  на чистой Java, в фоне.
- `TextArea.setMasked` — поле пароля. Заглушка `PlaceholderApp` удалена (все приложения настоящие). 48 новых строк ru/en.

### Тесты и dev
- `TdlibSmokeTest` (TDLib грузится и доходит до «введите номер»), `VideoNoteEncoderTest` (MP4 читается обратно, 15 кадров; обрезка).
- `DevShots`: сценарий `telegram`.

### Проверено
- `./gradlew build`, 17 тестов common + 15 тестов fabric.
- В игре (DevShots): экран ключей, TDLib внутри игры доходит до шага «номер телефона», запись «кружочка» из мира
  (49 кадров ≈ 3,3 с, 320×320, первый кадр — мир без интерфейса).

### Не проверено (нужен ручной тест)

- Загрузка нативной библиотеки из собранного jar мода (в среде разработки она лежит отдельно).

## [0.6.0] — 2026-10-20 — Этап 6: голосовые сообщения и звонки

### Протокол (common)
- `PROTOCOL_VERSION = 4`. `VoicePackets` (id 66–74): загрузка/скачивание голосовых кусками, состояние звонка, позвонить/ответить/выйти.
  `VoiceData` (VoiceRef, CallInfo, кодек ADPCM 16 кГц). `SendMessage.voiceId`, `MessageInfo.voice`.
  `SessionPacket` + maxVoiceSeconds, callsAvailable. Новые права `blockphone.voice`, `blockphone.call` (у всех).

### Сервер
- `VoiceService` + `VoiceRepository` (таблица voices, колонка messages.voice_id): голосовые до N секунд (настройка, по умолчанию 60),
  доступ только участникам чата, удаление вместе с сообщением/чатом, неотправленные чистятся через сутки.
- `CallService`: звонки в чатах через скрытые группы Simple Voice Chat — вызов всем участникам онлайн, ответ/отклонение,
  45 секунд на ответ, завершение, когда говорить не с кем; выход через меню SVC тоже учитывается.
- Интеграция с SVC в common: `VoiceBridge`/`VoiceBridges`/`SvcBridge`/`SvcPlugin` (API `voicechat-api` 2.6.0, compileOnly).
  Бэкенд получил планировщик (тик звонков раз в 5 с).
- Платформы: Fabric — точка входа `voicechat`; Paper — `softdepend` + `PaperVoicechat`; настройки `voice` в server.json / config.yml /
  config.json (Velocity — только голосовые, звонков на прокси нет).
- Тесты `VoiceServiceTest` (4: сессия, голосовое туда-обратно и доступ, звонок вдвоём, отклонение и выход из игры в группе).

### Клиент
- Голосовые в мессенджере: при пустом поле — микрофон; запись с индикатором громкости и таймером, «➤» — отправить, «×» — отмена,
  автоматическая отправка на пределе длины. Пузыри голосовых с «волной», проигрывание по нажатию (музыка встаёт на паузу).
  Кодек — свой IMA ADPCM 16 кГц (`Adpcm`): работает без других модов.
- Звонки: трубка в строке статуса чата, полоса идущего звонка (Войти/Ответить/Отклонить/Выйти, время, участники),
  окно входящего звонка поверх любого приложения, «рингтон», тосты, полоска звонка на экране игры.
- Иконки `textures/gui/voice/` (микрофон, трубка, сброс). 27 новых строк ru/en.

### Dev
- `DevShots`: сценарий `voice`. В среде разработки подключён сам Simple Voice Chat (`modLocalRuntime`).
- `AdpcmTest` (3 теста: качество > 20 дБ, крайние случаи, пересэмплирование).

### Проверено
- `./gradlew build`, 17 тестов common + 12 тестов fabric.
- В игре (DevShots): SVC загрузил плагин BlockPhone, мост к SVC работает (calls=true); голосовое загружено, показано и проигрывается;
  окно входящего звонка, полоса звонка, индикатор на HUD. Настоящий звонок отклонён сервером с понятной ошибкой
  (у dev-игрока выключен голосовой чат SVC до первоначальной настройки).

### Не проверено (нужен ручной тест)

## [0.5.0] — 2026-10-20 — Этап 5: музыка

### Плеер (`music/`)
- `MusicPlayer` + `Playback`: воспроизведение в отдельном потоке через `javax.sound`, очередь, пауза, перемотка, следующий/предыдущий,
  перемешивание, повтор (всё / один), подгружаемая очередь. Громкость плеера (настройка) × общая громкость игры. Играет и с закрытым телефоном.
- Декодеры: MP3 (JLayer, LGPL — встроен в мод), OGG (stb_vorbis из Minecraft, работает с русскими путями), WAV/AIFF/AU.
- Теги: ID3v2.2–2.4 и ID3v1 (русские теги в Windows-1251 читаются правильно), Vorbis comments; обложки из файлов.
- Своя музыка — папка `blockphone/music` (с подпапками); название из тегов или из имени файла «Исполнитель - Название».

### Яндекс Музыка (`music/yandex/`, неофициальный API)
- Вход: страница OAuth Яндекса → вставить адрес из браузера (токен вырезается сам). Токен — в `config/blockphone/accounts.json`.
- «Моя волна» (бесконечная, подгружается сама), «Мне нравится», поиск, лайк текущего трека, обложки.
- Треки скачиваются в `blockphone/cache/music` (последние 40) и играют как MP3. Без Плюса — отрывки.

### Spotify (`music/spotify/`)
- Пульт через Web API: подключение по шагам (своё приложение в Spotify for Developers → Client ID → вход в браузере, PKCE,
  ответ ловит мини-сервер на 127.0.0.1:43219). Что играет, обложка, пауза/вперёд/назад, перемотка, громкость, перемешивание, повтор.
  Управление требует Spotify Premium (ошибки 403/404 показываются понятным текстом).

### Интерфейс
- Приложение «Музыка» (вместо заглушки): вкладки «Моя музыка», «Яндекс», «Spotify», мини-плеер, полный плеер, очередь.
- Виджет «сейчас играет» на экране игры (слева сверху; плеер телефона или Spotify). Выключается в настройках.
- Настройки → «Музыка»: виджет на экране, громкость плеера. Новые клавиши: музыка пауза/следующий/предыдущий (не назначены).
- Иконки плеера (`textures/gui/music/`, `tools/gen_icons.py`). 64 новые строки ru/en.

### Тесты и dev
- `fabric/test`: `TrackTagsTest`, `YandexApiTest`, `SpotifyTest`, `OggDecoderTest` (9 тестов, проходят). Тестам доступен клиентский код.
- `DevShots`: сценарий `BLOCKPHONE_DEV_SCENARIO=music`.

### Проверено
- `./gradlew build`, 13 тестов common + 9 тестов fabric.
- В игре (DevShots): сканирование папки, воспроизведение OGG (позиция идёт в реальном времени), перемотка на 1:00,
  мини-плеер, полный плеер, виджет на HUD, экраны входа Яндекса и Spotify, тёмная тема.

### Не проверено (нужен ручной тест)
- MP3-файлы (нет тестового файла), WAV, теги и обложки настоящих файлов, клавиши музыки.
- Яндекс Музыка и Spotify целиком — нужны аккаунты игрока (Яндекс может изменить неофициальный API).

## [0.4.0] — 2026-10-20 — Этап 4: лента, паблики, фото, модерация

### Протокол (common)
- `PROTOCOL_VERSION = 3`. `ServerHelloPacket` + socialEnabled. Новые пакеты: `SessionPacket` (+ `Refresh`), `ImagePackets` (загрузка
  и скачивание фото кусками по 30 КБ), `SocialPackets` (id 30–65). Данные: `ImageRef` (+ `PhotoPolicy`, `Purpose`), `SocialData`.
- Сообщения мессенджера могут нести фото: `SendMessage.imageId`, `MessageInfo.image`.
- `PacketWriter/Reader`: int, enum, массив байтов с лимитом.

### Сервер (common/server)
- **`Backend`** — общий фоновый поток и база для мессенджера, ленты и фото (раньше поток и база были у мессенджера).
  `MessengerService` переведён на него; `UserRepository` выделен из `MessengerRepository`.
- Постоянный `serverId` (таблица meta) — для политики «только фото с этого сервера».
- **Права** (`Permission`): blockphone.post / .photo / .public.create (у всех), blockphone.moderate.posts / .publics / .mute / .reports
  и blockphone.moderator (у операторов) + список `moderators` в настройках. `ServerPlatform.hasPermission`.
- **`SocialService` + `SocialRepository`**: лента «Подписки» / «Все» с подгрузкой, посты от себя и от пабликов, лайки, комментарии
  (живые обновления у тех, кто смотрит пост), профили («о себе», подписчики, подписки), паблики (владелец, администраторы,
  подписка, поиск, популярные, лимит на игрока), жалобы, решения модераторов, заглушение (1 ч / сутки / 7 дней / навсегда),
  журнал модерации (таблица modlog + лог сервера), лимиты частоты, уведомления.
- **`ImageService` + `ImageRepository`**: фото хранятся в базе (общие для сети серверов), проверка политики, права, размера и формата
  (`ImageHeader` — PNG/JPEG по заголовку, без ImageIO), доступ: пост — всем, сообщение — только участникам чата;
  неприкреплённые загрузки удаляются через сутки.
- Тесты: `SocialServiceTest` (7 сценариев: сессия, посты/лента/лайки/комментарии, страницы ленты, паблики и админы, фото и доступ,
  жалобы/заглушение/модераторы, профиль) + общий `FakePlatform`. Всего 13 тестов — проходят.

### Платформы
- Fabric: `server.json` + social{...}, moderators; права через fabric-permissions-api (LuckPerms), если он есть, иначе op 2+.
- Paper: `config.yml` + social.*, moderators (новые ключи дописываются в старый файл); узлы прав регистрируются плагином.
- Velocity: `config.json` + social, moderators; права через LuckPerms Velocity. Версия плагина 0.4.0.

### Клиент
- Новое приложение **«Лента»** (видно на сервере с включённой лентой): вкладки Лента / Паблики / Профиль / Модерация (только
  модераторам), карточки постов (текст, фото, лайк, комментарии, меню: копировать / пожаловаться / удалить), пост с комментариями,
  «Новый пост» (от себя или от паблика, фото из галереи), профили (подписка, «Написать» — открывает чат, заглушение для модераторов),
  подписчики/подписки, поиск игроков и пабликов, создание и управление пабликом (название, описание, администраторы, удаление),
  очередь жалоб. Значок на иконке: новые посты в подписках + жалобы. Тосты о лайках, комментариях, подписках, жалобах.
- **Фото в мессенджере**: кнопка «+» у поля ввода, загрузка сразу после выбора, фото в пузырях, просмотр по клику; «[Фото]» в превью.
- Камера записывает в сведения о снимке `serverId`; выбор фото показывает, какие снимки разрешены политикой сервера.
- `ImageUploads` (уменьшение и JPEG до лимита сервера), `RemoteImages` (кэш `blockphone/cache/<сервер>/`), `ClientSession`.
- UI: `PhotoPicker`, `ImageViewer`, `Images`, `PopupMenu`; `Avatars.drawPublic`. Иконки: символ «Лента», лайк, комментарий, меню, фото
  (`tools/gen_icons.py`). 147 новых строк в ru/en.
- **Исправлено:** сброс состояния при выходе с сервера выполнялся в сетевом потоке (текстуры фото так освобождать нельзя) —
  теперь в потоке рендера.
